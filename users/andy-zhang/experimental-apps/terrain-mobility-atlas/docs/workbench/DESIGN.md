# Terrain Workbench design

The workbench is a separate numerical tool at `/workbench/`. The existing atlas remains at `/`. Its reference is the locally preserved `.references/design.posthog.html` from [yzfly/awesome-design-html](https://github.com/yzfly/awesome-design-html).

Use the reference's restrained cream background, olive text, amber actions, compact typography and flat bordered panels. The user's priority is readable quantities, plots and evidence. A world map, marketing hero, decorative mascot and biome coverage score add no value to this workflow and are excluded.

The working sequence is terrain selection and parameter evidence, mechanism configuration, calculation, and results. The node graph explains data dependencies; it is not a general purpose visual programming editor. A mechanism drawing establishes angle conventions. Histories and simultaneous torque–speed demand carry the engineering result.

The graph spans the content width, with the selected node's input/output contract beneath it in two columns. The 1,070 px graph canvas centers when space permits; compact layouts retain horizontal graph panning.

Terrain should be inspectable at route and wheel scales. A 1 km context, 100 m crop and short detail share one underlying realization. A roughness RMS control must not be mistaken for sine peak amplitude. Grade and obstacle dimensions have independent units and evidence. Dynamic results carry the scenario and model limitations beside the values.

Responsive layouts retain usable parameter labels, plot axes and graph navigation. Export controls preserve full numeric samples and case metadata even when display paths are reduced.
